01Overview

AI shows up in WorkRadar in two layers, and the project treats them differently.

AI inside the product. Google Gemini, orchestrated by n8n, writes the manager’s daily brief and triages Slack threads and emails, which have no priority or owner fields. It does not decide the ranking. A deterministic, explainable score does that, so every item can show why it is on the radar. Gemini runs under a JSON schema, its output is validated, and the app falls back to an on-device summary when no AI is reachable.

AI used to build the product. Claude (Anthropic) was the build partner from brief to delivery. It framed the problem, drafted the PRD, set the visual direction, wrote the React app and the n8n workflows, built a validation harness, and generated the Figma file from the running app. I set the constraints and made the product calls: the Airtribe context, n8n as the workflow engine, self-hosting instead of n8n Cloud, Gemini as the model provider, and the deadline. Every AI output went through a review pass before it shipped.

05Significant prompts

A · Daily brief

Where: n8n “Daily digest” and api/_prompt.ts, as one shared text

Model: Gemini Flash, temperature 0.3, responseMimeType: application/json + responseSchema

Design choices: facts-only rule, exact IDs so output can be validated, sentence-length caps so it fits the UI, and a fixed shape for each of the five sections.

You are WorkRadar, a chief-of-staff assistant for an engineering manager.
You receive a JSON snapshot of their team's work from Slack, Jira, GitHub and email.
Items are already ranked by a transparent priority score (0-100) and grouped into rings:
"now" (needs attention now), "today" and "later".
Write the manager's brief as JSON that matches the response schema.

Rules
- Use only facts in the snapshot. Never invent people, numbers, deadlines or items.
- Put the exact item "id" from the snapshot in every itemId field. Use team member ids for personId.
- Plain, specific language. No hype, no emojis, no exclamation marks.
- Each "why", "action" and "suggestion" is one sentence under 25 words.

Fields
- headline: 1-2 sentences. How many items need attention, how many people are blocked
  (and how many on the manager), and the one thing to start with and why.
- topWork: exactly 3 items the manager should personally act on today ... "why" is the concrete next step.
- happened: up to 6 notable events from happenedToday as short past-tense sentences.
- attention: every item in ring "now" (max 6), with why it matters now and the action to take.
- blocked: one entry per blocked person with personId, itemId, blockedOn, since and suggestion.

B · Thread triage

Where: n8n “Source ingestion”, Prepare AI triage → Gemini

Model: Gemini Flash, temperature 0.2, schema with a P0–P3 | NONE enum and booleans. The results are merged into each item’s signals before scoring.

Design choices: Airtribe-specific P-level definitions anchored on learners and revenue; the team roster plus skills, for owner suggestions; FYIs filtered out before the call to save tokens.

You triage workplace messages for Neha Kapoor, Engineering Manager of the Learning Platform team
at Airtribe (an online learning company running live cohort programs).
For every thread, return one object in "results" with:
- priority: P0 (live incident hurting learners now), P1 (urgent, learners or revenue affected),
  P2 (normal), P3 (low), or NONE for FYI
- waitingOnManager: true only if someone is explicitly waiting for Neha to decide, review or reply
- blocked: true if a teammate says they cannot proceed
- escalation: true for incidents or escalations from leadership or customers
- summary: one plain sentence under 30 words with the key facts (numbers, deadlines)
- nextStep: one sentence under 25 words telling the manager what to do
- suggestedOwner: the team member id best placed to own it, or "" if it is the manager's own decision
Use only the facts in the text. Team: [{"id":"rahul","role":"Senior Frontend Engineer","skills":[...]}, ...]
Prompts are quoted from the repository (api/_prompt.ts, n8n/src/ingest-classify-request.js); “...” marks shortening.2 / 4

Prompting patterns that worked

  • Ask for a plan and questions first. “Prepare a list of what you need from me” turned a vague brief into five concrete decisions before any code was written.
  • Give the model the business definitions. P0–P3 anchored on learners and revenue made triage consistent with how Airtribe actually prioritises.
  • Constrain output to the UI. Schema fields map one-to-one to UI slots, with word limits sized to the layout.
  • Make hallucinations detectable. Requiring exact item IDs means any invented item can be dropped automatically.
  • One prompt, many runtimes. The brief prompt lives in one file that n8n and Vercel both use, so the engines can’t drift.
  • Review against screenshots, not code. Most quality issues (ranking surprises, copy, truncation) were only visible on the rendered screen.

07Key trade-offs

Guardrails and how the AI is checked

  • Facts-only prompting with exact IDs, then validation that drops anything the snapshot can’t support.
  • Every score is explained by factor in the UI, so the manager can disagree and re-weight.
  • An engine label on every brief (Gemini, Gemini via n8n, n8n rule-based, on-device), so users know what they’re reading.
  • The pipeline simulator (n8n/validate.mjs) replays ingestion → triage → score in CI. The expected top three are the iPhone incident (97), PR #1284 (93) and LP-512 (86).
  • Graceful failure: the outage banner hides a down source and explains the effect on ranking. AI errors offer a retry or the on-device summary.
  • Secrets stay only in n8n credentials and Vercel env. The browser never sees the key.

What I’d do next with AI

  • An eval set: 50 golden snapshots with expected top-3 lists, plus an LLM-as-judge faithfulness check on every brief, tracked weekly.
  • Learned weights: tune the six weights per manager from opens, snoozes and reorders, keeping the explanation.
  • Reply drafts: Gemini drafts responses for “waiting on you” asks, sent only after the manager approves.
  • Write-back through n8n: Jira assign, GitHub review requests and Slack replies, with an audit log and undo.
  • Cost and latency dashboards from n8n execution data, with budget alerts per team.
  • A privacy layer: redact personal data before triage, and keep message bodies for at most 7 days.
LessonThe most useful AI work wasn’t generating code. It was generating options and then critiquing the result from the user’s point of view. The biggest quality jumps came from review passes against real screenshots, not from longer build prompts.
